# Implementation Plan: Context Compression for Long Conversations

**Branch**: `014-context-compression` | **Date**: 2026-04-22 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/014-context-compression/spec.md`

## Summary

When a session's token count exceeds 75% of the model's context window, `Agent.run()` uses `client.messages.countTokens()` to get an exact count, calls `fastModel` to summarize the older messages, persists the summary to a new `summary` column in SQLite, then rebuilds the context with the summary at the head and the most recent 20 messages verbatim. Users are notified via a new `"system"` role message in the CLI.

**Scale/Scope**: All sessions share the same compression path; summary stored per-session

## Phase 1: Design

### 1. `packages/core/src/agent/models.ts` (new)

Move the context window map here from CLI:

```typescript
const MODEL_CONTEXT_LIMITS: Record<string, number> = {
  "claude-opus-4-6": 200_000,
  "claude-sonnet-4-6": 200_000,
  "claude-haiku-4-5": 200_000,
};

export function getContextLimit(modelName: string): number {
  for (const [prefix, limit] of Object.entries(MODEL_CONTEXT_LIMITS)) {
    if (modelName.startsWith(prefix)) return limit;
  }
  return 200_000;
}
```

### 2. `packages/core/src/agent/compressor.ts` (new)

Core compression logic:

```typescript
export interface CompressorOptions {
  client: Anthropic;
  model: string;        // active model (for token counting)
  fastModel: string;    // model to use for summarization
  system?: string;      // system prompt (included in token count)
  threshold: number;    // e.g. 0.75
  keepRecentCount: number; // e.g. 20
}

export interface CompressResult {
  messages: MessageParam[];  // rebuilt context: [summary-pair, ...recent]
  compressedCount: number;
  keptCount: number;
}

// Returns null if no compression needed; throws on failure
export async function compressIfNeeded(
  messages: MessageParam[],
  options: CompressorOptions,
): Promise<CompressResult | null>
```

Internal steps:
1. Fast-path: if `messages.length ≤ keepRecentCount` → return `null` immediately (no API call — satisfies SC-006)
2. Call `client.messages.countTokens({ model, messages, system })` → `input_tokens`
3. Compute threshold: `getContextLimit(model) * threshold`
4. If `input_tokens < threshold` → return `null`
4. Split: `toSummarize = messages.slice(0, -keepRecentCount)`, `recent = messages.slice(-keepRecentCount)`
5. If `toSummarize.length === 0` → throw `ContextTooLargeError` (even recent messages overflow)
6. Call `client.messages.create({ model: fastModel, max_tokens: 2048, messages: summarizationPrompt })`
7. Return `{ messages: [summaryUserMsg, summaryAssistantAck, ...recent], compressedCount, keptCount }`

Summarization prompt structure (step 6):
```
[user]: Please summarize the following conversation history into a structured format covering:
## Current Task
## Completed Actions  
## Key Decisions & Facts
## User Preferences & Constraints

<history>
{toSummarize as JSON}
</history>

[assistant]: (generated summary)
[user (synthetic)]: <context_summary>{summary}</context_summary>
[assistant (synthetic)]: Understood. I have the context from earlier in this session.
```

```typescript
// In constructor, after existing try/catch migrations:
try {
  this.db.run("ALTER TABLE sessions ADD COLUMN summary TEXT DEFAULT NULL");
} catch { /* already exists */ }

async getSessionSummary(id: string): Promise<string | null> {
  const row = this.db.prepare<{ summary: string | null }, string>(
    "SELECT summary FROM sessions WHERE id = ?"
  ).get(id);
  return row?.summary ?? null;
}

async setSessionSummary(id: string, summary: string): Promise<void> {
  this.db.prepare("UPDATE sessions SET summary = ? WHERE id = ?").run(summary, id);
}
```

## Key Implementation Notes

1. **Summary injection on session load**: The `getSessionSummary` call happens every turn (not just when compression fires). If a summary exists from a previous session or turn, it is prepended before the token count check. This means re-compression naturally incorporates the existing summary.

2. **`AgentConfig` extension**: `AgentConfig` in `types.ts` needs a `contextCompression?: ContextCompressionConfig` field so callers can override it. The CLI and API wire it from `loadConfig()`.

3. **Error type**: Create a `ContextTooLargeError` class for the case where even recent messages alone exceed the threshold. This gives callers a typed error to handle distinctly from network failures.

4. **Export alignment**: `packages/core/src/index.ts` needs to export `CompressionInfo`, `getContextLimit`, and `ContextTooLargeError` for consumers.

5. **Test strategy**: 
   - Unit test `compressIfNeeded()` with a mock client that returns fixed token counts
   - Unit test the summary-injection logic in `Agent.run()` using in-memory SQLite
   - Unit test `SQLiteStorageAdapter` `getSessionSummary` / `setSessionSummary`
   - Unit test `getContextLimit()` for known and unknown model names
