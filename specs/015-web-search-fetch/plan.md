# Implementation Plan: WebSearch + WebFetch Tools

**Branch**: `015-web-search-fetch` | **Date**: 2026-04-24 | **Spec**: `specs/015-web-search-fetch/spec.md`

## Summary

Add two complementary agent tools — `web_search` (DuckDuckGo via pure TypeScript HTTP) and `web_fetch` (URL retrieval with HTML→Markdown conversion and optional fast-model processing) — backed by an extensible `SearchProvider` interface in `packages/core/src/search/`. Config extended with a `[search]` TOML section. No Python dependency.

## Technical Context

**Language/Version**: TypeScript 5.x, Bun ≥ 1.3.12
**Primary Dependencies**: `@anthropic-ai/sdk` (existing), `node-html-parser` (new), `turndown` (new), `@types/turndown` (new dev)
**Storage**: N/A — tools are stateless
**Testing**: `bun test`
**Target Platform**: Linux/macOS (Bun standalone binary)
**Project Type**: Monorepo library (`packages/core`) + CLI (`packages/cli`) + API (`packages/api`)
**Performance Goals**: `web_search` < 3s, `web_fetch` (no model) < 5s, `web_fetch` (with model) < 15s
**Constraints**: No Python; no subprocess; Biome-clean; strict TypeScript

## Research Basis

Three parallel agents explored the codebase. Key findings:
- Non-streaming `client.messages.create()` is the correct pattern for tool sub-calls (see `subagent.ts`)
- `createDefaultTools()` in `tools/index.ts` is the registration point; factory closure is the config-passing pattern
- `section()` helper in `config.ts` handles missing TOML sections gracefully
- DuckDuckGo endpoint: POST `https://html.duckduckgo.com/html/` with `q=`, `User-Agent` required

Full findings: `specs/015-web-search-fetch/research.md`

## Implementation Phases

### Phase 1: Search module + config

1. **Add `SearchConfig` to `config.ts`**
   - Add `SearchConfig` interface: `{ provider: string; braveApiKey?: string }`
   - Add `search: SearchConfig` to `ChloeConfig`
   - Add `searchProvider: "duckduckgo"` to `DEFAULTS`
   - In `loadConfigFrom`: extract `fileSearch = section(raw, "search")`, derive with env→TOML→default priority, return `search: { provider: searchProvider }`
   - Env var: `CHLOE_SEARCH_PROVIDER`

2. **Create `packages/core/src/search/types.ts`**
   ```ts
   export interface SearchResult { title: string; url: string; snippet: string; }
   export interface SearchOptions { maxResults?: number; }
   export interface SearchProvider {
     search(query: string, options: SearchOptions): Promise<SearchResult[]>;
   }
   ```

3. **Create `DuckDuckGoProvider`** (`search/providers/duckduckgo.ts`)
   - POST `https://html.duckduckgo.com/html/` with `q=<query>&l=us-en&kp=-1`
   - Headers: `User-Agent: Mozilla/5.0 ...`, `Content-Type: application/x-www-form-urlencoded`
   - Parse HTML: `node-html-parser` → select `.result` containers → extract `.result__a` (title + href) and `.result__snippet`
   - Decode DDG redirect URLs: extract `uddg` param from `/l/?uddg=<encoded>`, `decodeURIComponent`
   - Filter out `https://duckduckgo.com/y.js?` URLs
   - Respect `maxResults` (slice result array)

4. **Create `BraveProvider` stub** (`search/providers/brave.ts`)
   - Throws `new Error("Brave Search provider not yet implemented. Set [search] provider = 'duckduckgo' in config.")` 

5. **Create `search/index.ts`** — `getSearchProvider(config: SearchConfig): SearchProvider`
   ```ts
   export function getSearchProvider(config: SearchConfig): SearchProvider {
     switch (config.provider) {
       case "duckduckgo": return new DuckDuckGoProvider();
       case "brave": return new BraveProvider(config.braveApiKey ?? "");
       default: return new DuckDuckGoProvider();
     }
   }
   ```

### Phase 2: `web_search` tool

6. **Create `tools/web-search.ts`**
   - Factory: `createWebSearchTool(searchConfig: SearchConfig): Tool`
   - Calls `getSearchProvider(searchConfig).search(query, { maxResults })`
   - Returns JSON string of `SearchResult[]`
   - Input schema: `{ query: string, max_results?: number }`
   - Validate: clamp `max_results` to 1–20

### Phase 3: `web_fetch` tool

7. **Install npm deps**: `bun add node-html-parser turndown && bun add -d @types/turndown`

8. **Create `tools/web-fetch.ts`**
   - Factory: `createWebFetchTool(): Tool`
   - Fetch URL with `Bun.fetch()`, check `Content-Type` — reject non-HTML with error
   - Strip `<script>`, `<style>`, `<nav>`, `<footer>` nodes via `node-html-parser`
   - Convert to Markdown via `turndown`
   - Truncate to 50,000 chars
   - If `process: false` → return Markdown directly
   - If `process: true` → call `context.client.messages.create({ model: context.modelConfig.fastModel, max_tokens: 2048, messages: [{ role: "user", content: prompt + "\n\n" + markdown }] })`
   - Default prompt: `"Summarize the key information from this web page content concisely."`
   - If `context` is undefined → return raw truncated Markdown as fallback

### Phase 4: Wire up

9. **Modify `tools/index.ts`** — `createDefaultTools()` signature:
   ```ts
   export function createDefaultTools(
     settings: ToolSettings,
     cwd: string,
     permissionRef?: ...,
     searchConfig?: SearchConfig,
   ): Tool[]
   ```
   Add `createWebFetchTool()` unconditionally. Add `createWebSearchTool(searchConfig)` only when `searchConfig` is provided.

10. **Modify `agent.ts`** — pass `config.search` to `createDefaultTools()`.

### Phase 5: Tests

11. **Unit tests for `DuckDuckGoProvider`**
    - Mock `fetch` — test result parsing with fixture HTML
    - Test URL decoding from DDG redirect format
    - Test `maxResults` clamping

12. **Unit tests for `web-search` tool**
    - Test with mocked provider
    - Test input validation (missing `query`, out-of-range `max_results`)

13. **Unit tests for `web-fetch` tool**
    - Test with mocked `fetch` returning HTML fixture
    - Test `process: false` returns Markdown
    - Test `process: true` calls model with correct prompt
    - Test truncation at 50,000 chars
    - Test non-HTML content-type returns error
    - Test `context` undefined fallback

14. **Unit tests for config**
    - Test `loadConfigFrom` with `[search]` section
    - Test `loadConfigFrom` without `[search]` section (default `"duckduckgo"`)
    - Test `CHLOE_SEARCH_PROVIDER` env var override
